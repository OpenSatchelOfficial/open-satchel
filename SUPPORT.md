# Getting Help with Open Satchel

How to get answers, file bugs, or reach the right inbox.

---

## I have a question about using the app

Start with:

1. **[docs/getting-started.md](docs/getting-started.md)** — 20-minute
   walkthrough of the most-used features.
2. **[docs/features.md](docs/features.md)** — full feature reference.
3. **[docs/KNOWN-LIMITATIONS.md](docs/KNOWN-LIMITATIONS.md)** — the
   things Open Satchel cannot do yet, with workarounds.

If those don't answer it, [open a GitHub issue](https://github.com/JayQuan-McCleary/open-satchel/issues)
with the `[question]` prefix in the title. Best-effort response.

Commercial license holders should email the address listed in their
license agreement for prioritized response.

---

## I found a bug

Open a GitHub issue with reproduction steps, your OS + version, and
the app version (from `About`). See [CONTRIBUTING.md](CONTRIBUTING.md)
for the format that gets fastest triage.

---

## I think I found a security issue

**Do not file a public issue.** Email `security@opensatchel.dev`.
Acknowledgement within 72 hours; details in [SECURITY.md](SECURITY.md).

---

## I want to buy a commercial license

- Self-serve checkout for Small / Mid / Large tiers:
  [opensatchel.dev/licensing](https://opensatchel.dev/licensing)
- Nonprofit / education verification: application form on the licensing page
- Engine SDK / Source / OEM / enterprise: email `licensing@opensatchel.dev`

---

## I have a procurement / legal / privacy question

| Topic | Where |
|-------|-------|
| Security questionnaire (SBOM, SSDF, controls mapping) | [docs/COMPLIANCE-CHECKLIST.md](docs/COMPLIANCE-CHECKLIST.md) + [docs/SBOM.md](docs/SBOM.md) + [docs/SSDF-ATTESTATION.md](docs/SSDF-ATTESTATION.md) |
| Air-gap / no-network audit | [docs/AIRGAP-AUDIT.md](docs/AIRGAP-AUDIT.md) |
| Accessibility (Section 508, PDF/UA) | [docs/ACCESSIBILITY.md](docs/ACCESSIBILITY.md) |
| Privacy / data flow | [PRIVACY.md](PRIVACY.md) |
| Reproducible build verification | [docs/REPRODUCIBLE-BUILD.md](docs/REPRODUCIBLE-BUILD.md) |
| BAA, DPA, custom legal terms | `licensing@opensatchel.dev` (enterprise/source/OEM tier) |
| Vulnerability disclosure history | `security@opensatchel.dev` |

If none of the above fit, email `licensing@opensatchel.dev` and
we will route it.

---

## I want to suggest a feature

[Open a GitHub issue](https://github.com/JayQuan-McCleary/open-satchel/issues)
with `[feature]` in the title and a real use case. The use case
matters more than the feature itself — see [CONTRIBUTING.md](CONTRIBUTING.md).

---

## I want to contribute code

Please read [CONTRIBUTING.md](CONTRIBUTING.md). Open Satchel does not
accept external code contributions at this time because of how the
dual-licensing model interacts with copyright ownership. Bug reports,
feature requests, and documentation feedback are all warmly welcome.

---

## I want to talk to a human

For commercial / procurement matters: `licensing@opensatchel.dev`.
For security: `security@opensatchel.dev`. For everything else: file a
GitHub issue and we will respond there.

Open Satchel is run from Kingston, Jamaica (EST, no DST). Most replies
land within 1-2 business days.
