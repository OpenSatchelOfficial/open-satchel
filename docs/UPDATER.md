# Auto Updates

Open Satchel uses the Tauri v2 updater. Release bundles are signed at
build time, and the app installs only artifacts whose signature matches
the updater public key embedded in `src-tauri/tauri.conf.json`.

## Feed

The production app checks:

```text
https://github.com/OpenSatchelOfficial/open-satchel/releases/latest/download/latest.json
```

GitHub Releases must therefore include `latest.json` plus the platform
bundles and `.sig` files generated by Tauri.

## Signing Key

The public key is safe to commit and is already configured in
`src-tauri/tauri.conf.json`.

The private updater key must never be committed. For local release
builds, keep it outside the repository, for example:

```text
%USERPROFILE%\.tauri\open-satchel-updater.key
```

For GitHub Actions, add the private key contents as a repository secret:

```text
TAURI_SIGNING_PRIVATE_KEY
```

If you regenerate a password-protected key, also add:

```text
TAURI_SIGNING_PRIVATE_KEY_PASSWORD
```

Losing the private key means shipped installs cannot trust future
updates from a replacement key. Treat it as a launch credential.

For the current passwordless local key, release builds must still set
the password environment variable explicitly to the empty string:

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = Get-Content -Raw $env:USERPROFILE\.tauri\open-satchel-updater.key
$env:TAURI_SIGNING_PRIVATE_KEY_PASSWORD = ''
npm run tauri:build
```

## Release Flow

1. Bump both versions:
   - `package.json`
   - `src-tauri/tauri.conf.json`
2. Update `CHANGELOG.md`.
3. Push a tag such as `v0.1.1`.
4. Let `.github/workflows/release.yml` build the signed artifacts.
5. Confirm the GitHub release contains `latest.json`, installers, and
   matching `.sig` files.

The installed app checks for updates on startup and exposes a manual
check in About -> Updates.
